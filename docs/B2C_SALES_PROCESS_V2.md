# B2C 영업 절차 v2

2026-10-16 사용자가 전달한 `WARP_영업프로세스_변경_승인요청서_v2.docx`의 적용안이다. B2B는 기존 체크·전환 절차를 사용한다.

## 단계 전환

- 미성숙 → 잠재: 실제 전화통화 완료. 배송업 의향/연락 가능 기록을 통화로 치환하지 않는다.
- 잠재 → 성숙: 구매의사와 1차 견적 발송을 모두 확인한다.
- 성숙 → 판매신청: 고객과 최종 견적을 확정하고, 확정일·모델·주요 사양·원 단위 금액·해당 리드의 견적 자료를 기록한다. 기존 발송 체크는 확정과 별개다.
- 판매신청 → 다음 단계: EV& 계약금 100,000원, 실제 은행 입금일, 모델·주요 사양과 해당 리드의 송금 증빙을 확인한다. KIA 입금은 기존 별도 항목으로 유지한다.
- 화면/API/엑셀 가져오기에서 앞으로 이동할 때 건너가는 관문을 검사한다. 현재 단계 유지·메모 변경·이전 단계 이동은 과거 관문을 새로 증명하도록 강제하지 않는다.

## 기록 보존과 신규 유입

미성숙 단계의 문의 상태는 상담 대기(기본값)와 부재중 대기 중 하나를 직접 선택한다. 기존 신규 문의 값은 화면과 저장 시 상담 대기로 해석한다. 재연락 일시와 정정 사유 입력은 미성숙 화면에서 제외하며, 기존 재연락 기록은 삭제하지 않는다. 견적·계약금 정정 사유는 해당 단계에서 계속 기록한다.

전화통화 완료 체크 시 문의 상태는 첫 상담 완료로 표시하고 체크와 함께 저장한다. 체크 해제 시 상담 대기로 돌아간다. 첫 상담 완료는 수동 선택으로 통화를 대신할 수 없으며, 이전 배송업 의향 체크를 통화 완료로 해석하지 않는다. PC 목록과 모바일 카드에 B2C 미성숙의 문의 상태를 표시하고, 미성숙 단계에서 상태별 필터를 제공한다. 이미 통화 완료한 기존 기록도 동일하게 표시하되 일괄 데이터 변경은 하지 않는다.

마이그레이션은 nullable JSON과 revision, 변경 이력 테이블만 추가한다. 현재 단계/체크/메모/기존 서류를 백필하거나 일괄 하향하지 않는다. 문서 작성 뒤 추가된 차량 시승·판매방법도 유지한다. 1차/최종 견적 첨부를 구분하되 기존 `quotation` 자료도 확정 근거로 선택할 수 있다.

EV&Marketing의 신규 customer-lead-v1 접수는 미성숙 1-1에서 시작하며 아무 체크도 자동 완료하지 않는다. 과거 전송 영수증의 재처리는 기존 고객·리드·단계를 유지한다. 외부 API의 인증/응답/쓰기 범위는 유지한다.

## 계약금과 출고 대기

같은 모델·주요 사양 문구를 공백/대소문자 정규화 후 묶고 실제 입금일·입금시각으로 정렬한다. 모델·주요 사양은 확인된 견적과 같은 명칭으로 입력한다. 사양 분류를 임의로 추론하지 않는다.

- 미입금, 입금일·자료 미확인, 다른 금액, 환불/취소/보류/종료는 순번을 부여하지 않는다.
- 같은 날 입금한 건 중 시각이 없거나 동일 시각이면 담당자 확인 전 순번을 확정하지 않는다.
- 이미 기록한 입금일·시각·모델·사양·금액 등의 변경에는 사유가 필요하며 순번 재검토 상태가 된다. 새로 저장된 사실을 다시 확인하고 사유와 함께 검토 상태를 해제한다. 환불/취소 상태에서는 해제해도 순번이 생기지 않는다.
- 과거 입금일에 오늘 날짜를 채우지 않는다. 실제 출고 일정/캐피탈/특장 공정은 기존 운영을 따른다.

영업 절차, 필수 체크, 단계, 수정 전후 값, 확인자, 사유는 동일 트랜잭션으로 저장한다. 충돌 시 409로 새로 확인하도록 한다. 이력에 사용된 견적·송금 증빙은 삭제하지 않고 새 자료를 추가한다. 일반 리드 권한으로 조회 범위를 제한한다.

## 운영 적용 및 검증

공식 main release만 사용한다. 추가형 SQL은 기존 런타임과 호환되며 전역 고객정보나 B2B 데이터를 일괄 수정하지 않는다. 기존 버전으로 롤백할 경우 새 관문 검사가 없어지므로 단기 복구에 한정한다.

- `npm run test:sales-process`: 관문/건너뛰기/기존 기록/날짜/순번/수정 사유/충돌/증빙/트랜잭션 검증
- `npm run test:marketing-inquiries`: 신규 미성숙 접수와 과거 영수증 재처리 보존
- `npm run test:deployment`: 기존 DB 보존 및 변경 이력 수정·삭제 거부 포함
- `npm run typecheck`, 연동 계약 검사, 보안 검사
- 별도 가상 DB에서 실제 HTTP 저장 및 PC/390px 모바일 화면 확인. 실제 고객에게 테스트 리드·계약금은 만들지 않는다.
